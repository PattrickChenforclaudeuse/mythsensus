# คำอ่านรายศาสตร์ (one-off) — สองชั้น

> สถานะ 2 ก.ย. 69 · **ทำงานได้ครบวงจรในเครื่อง ยังไม่ต่อเข้าท่อขาย**
> ของที่ขายอยู่ตอนนี้ยังเป็น `oracle-render` ตัวเดิม (6 หมวด × 10 คำถาม) ไม่ถูกแตะ

## ทำไมต้องสองชั้น

director 2 ก.ย.: *"เขาไม่ได้ต้องการการตอบเป็นข้อๆ เราได้คำตอบมา engine ต้องมีหน้าที่เรียบเรียงต่อด้วย
ส่วนที่เป็นข้อๆเอาไว้สำหรับทำ consensus"*

| ชั้น | ผลลัพธ์ | ใครใช้ |
|---|---|---|
| 1 · answers | คำตอบ 45 ข้อ เป็น JSON มีรหัสข้อกำกับ | **เครื่อง** — เอาไปเทียบข้ามศาสตร์ทำ consensus · ลูกค้าไม่เห็น |
| 2 · compose | ความเรียง 6 บท ไม่มีเลขข้อ ไม่มีคำถาม | **ลูกค้า** |

**ทำไมไม่ทำชั้นเดียว** — ลองแล้วเป็นชั้นเดียว (ตอบทีละข้อ) ผลคือซ้ำหนัก
เพราะทุกข้อต้องไล่ที่มาใหม่ตั้งแต่ต้น วัดได้: วลีซ้ำข้ามข้อ **37 วลี** · ศัพท์ 傷官
ถูกยกมาอธิบายใหม่ **12 ครั้งใน 45 ย่อหน้า** · พอเรียบเรียงเหลือ **วลีซ้ำ 1** และอธิบายศัพท์ครั้งเดียว

## วิธีรัน

```bash
./run.sh bazi              # ครบวงจร
./run.sh bazi --skip-gen   # เรนเดอร์ + ตรวจใหม่ ไม่เรียกโมเดล
```

ไฟล์ที่เกิด: `payload-<sys>.json` → `out-<sys>.json` (ชั้น 1) → `compose-<sys>.json` (ชั้น 2) → `oneoff-<sys>.html`

## ข้อห้ามที่แลกมาด้วยของพัง

- ⛔ **ต้องวิ่งผ่าน subscription (`claude -p`)** — `run.sh` หยุดเองถ้าเจอ `ANTHROPIC_API_KEY` ใน environment
- ⛔ **ตัวเลขในภาพต้องอ่านจาก payload ของเอนจิน ห้ามให้โมเดลป้อน** ไม่งั้นภาพกับข้อความเถียงกันบนหน้าเดียว
- ⛔ **ห้ามลอกตารางของเอนจินมาไว้ในตัวเรนเดอร์** — สมดุลห้าธาตุเคยวาดไม่ได้เพราะเหตุนี้
  แก้ด้วยการเปิด `bazi.elementCounts` ออกมาจากเอนจิน แล้วภาพอ่านจากที่นั่นที่เดียว
- ⛔ **สีในกราฟบอกได้เรื่องเดียว** — เคยให้สีบอกทั้ง "บทบาทของธาตุ" และ "มีหรือไม่มี" พร้อมกัน
  น้ำเป็นธาตุมงคลแต่มี 0 ตัว เลยถูกวาดเป็นเทาว่า "ไม่มี" ทั้งที่มันคือพระเอกของดวง
  ⇒ ความว่างบอกด้วยรูปทรง (เส้นประ) ไม่ใช่ด้วยสี
- ⛔ **ห้ามอีโมจิ** (director 2 ก.ย.)
- ⛔ **ข้อที่ศาสตร์นั้นไม่มีวิชาตอบ ต้องบอกว่าไม่มี ห้ามแต่งให้ครบ 45 ข้อ** —
  BaZi ตอบได้ 43/45 · ที่ตอบไม่ได้ไปโผล่ในตาราง "เรื่องที่ศาสตร์นี้อ่านไม่ได้" หน้าสุดท้าย

## ด่านวัด

`node check-compose.cjs compose-<sys>.json out-<sys>.json` — วัด 7 อย่าง เพราะคำว่า
"ซ้ำ / fluff / เรียบเรียงไม่ดี" วัดได้ทั้งหมด ไม่ต้องเถียงกันด้วยความรู้สึก

วลีซ้ำข้ามย่อหน้า · ศัพท์ที่ถูกยกมาบ่อยเกิน · **สรรพนามหลุด** · หัวข้อที่เป็นคำถาม ·
วลีกลวง · ย่อหน้าบวม · ข้อที่หล่นหาย

> ด่านสรรพนามมีเพราะรอบแรกเขียนถึงผู้อ่านว่า「เขา」15 ครั้ง「คุณ」1 ครั้ง
> = รายงานเกี่ยวกับคนอื่น ไม่ใช่คำอ่านถึงเจ้าตัว ตาเปล่าอ่านผ่านไปไม่รู้สึก

## ⚠️ ยังต่อเข้าท่อขายไม่ได้ตรงๆ — วัดแล้วติดสามอย่าง

`supabase/functions/oracle-render/index.ts` ตอนนี้ `MAX_TOKENS = 7000`, `RENDER_TIMEOUT_MS = 140_000`,
ยิง Anthropic **ครั้งเดียว**

| | ที่วัดได้จริง | เพดานที่มี |
|---|---|---|
| ชั้น 1 (45 ข้อ) | ≈ 22,000 tokens | 7,000 |
| ชั้น 2 (เรียบเรียง) | ≈ 12,000 tokens | 7,000 |
| เวลาชั้น 1 หนึ่งก้อน | > 600 วินาที | 140 |

**เพดาน 7,000 คือเหตุผลที่ของที่ขายอยู่ตอนนี้ออกมาหน้าเดียว** ไม่ใช่เพราะเขียนสั้น

ทางที่น่าจะถูก (ยังไม่ได้ทำ ต้องให้ director เคาะเพราะแตะของที่ขายอยู่):
- ชั้น 1 **แตกเป็น 10 ก้อนตามหมวด ยิงขนาน** ก้อนละ ~2,200 tokens ลงใต้เพดานสบาย และเวลาเหลือแค่ก้อนที่ช้าที่สุด
- ชั้น 2 ยิงครั้งเดียวหลังชั้น 1 ครบ ต้องยก `MAX_TOKENS` เป็น ~16,000
- ต้นทุนต่อเล่มจะขึ้นจาก 1 call เป็น 11 calls — ต้องคิดใหม่ว่าคุ้มกับราคาขาย $9 ไหม
- ของเดิมยังต้องอยู่ได้ระหว่างเปลี่ยน: คีย์แคชมี `prompt_version` อยู่แล้ว
  ⇒ ขึ้นเวอร์ชันใหม่ แถวเก่าไม่พัง ถอยกลับได้ด้วยการสลับ `prompt_version` กลับ
